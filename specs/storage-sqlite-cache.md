# 从 dev 分支移植存储后端与解析缓存

状态：已完成 · 优先级：中

## 背景

`dev` 分支实现了 SQLite 存储、LRU 缓存和数据同步工具，但它和 master 已严重分叉，架构也不同。直接合并等于在两套架构之间二选一，所以把功能重新实现到 master 现有结构上，不合并 `dev`。

## 目标

部署可以选择 SQLite 替代 Redis，可以开启解析缓存，已有 Redis 数据可以迁移到 SQLite。现有部署升级后无需修改配置，行为不变。

## 范围

- 在 `shortURLMappings` 下引入 `mappingStore` 接口，由 Redis 和 SQLite 分别实现。
- 新增可选的解析缓存，默认关闭。
- 新增 `sync-redis-to-sqlite` 子命令。
- 运行镜像从 `scratch` 改为 `alpine:latest`。

## 不在范围内

- 缓存清空接口。缓存条目最长只存活一个缓存 TTL，映射又不会被修改，需要时重启即可。
- `internal/` 分层、`web/` 和 `output/` 目录改名。
- 环境变量改名和 TOML 配置文件。现有部署不应因升级而修改配置。
- `dev` 的校验规则。master 的规则已经更严格。

## 与 dev 的行为差异

**SQLite**

- 查询时过滤过期数据，不做懒删除。`dev` 的懒删除不带过期条件，可能删掉刚重新创建的映射。
- 每条连接都设置 `busy_timeout` 和 WAL。`dev` 在并发写入时可能报 `database is locked`。
- `Close` 会停止后台清理。
- 映射在 `expires_at > now` 时有效，在 `expires_at <= now` 时可被覆盖，不留边界间隙。
- 使用 `database/sql` 和 `modernc.org/sqlite`，不引入 GORM。表结构与 `dev` 一致，`dev` 的数据库文件可以直接使用。

**解析缓存**

- 条目保存时长取映射剩余有效期和缓存 TTL 中较短的一个。`dev` 对会过期的映射直接使用剩余有效期，缓存 TTL 实际不生效。
- 默认关闭。`dev` 的代码默认开启，配置文件默认关闭，两者矛盾。
- 位于 `shortURLMappings` 层，不在每种存储中重复实现。

**同步工具**

- 有 key 同步失败时以非零退出码退出。`dev` 只打印日志。
- 不覆盖目标中的有效映射，可以重复执行。`dev` 会覆盖。
- 永久 key 保持永久。`dev` 改为 10 年有效期。

## 验收标准

- [x] 不设置新配置时，升级后行为与之前一致。
- [x] 创建和解析的共同行为在 Redis 和 SQLite 上用同一套测试验证。
- [x] 32 个并发请求抢占同一短键时恰好一个成功，SQLite 上不出现 `database is locked`。
- [x] 使用 SQLite 时无需 Redis 即可启动，容器重启后数据仍在。
- [x] 存储类型或缓存配置无效时拒绝启动。
- [x] 同步后带 TTL 的映射保留有效期，永久映射保持永久，再次执行结果不变，失败时退出码非零。
- [x] 缓存条目不会比映射存活更久。
- [x] CI 构建的全部架构都能编译，`go test -race ./...` 通过。
